# v0.1.0 — Approved Memory Mirror

HERmes v0.1.0 is a local approved-memory CLI. It proves a small safe baseline: intake creates drafts, only explicit approval creates approved memory, and reflection/search read approved memory only.

## What Shipped

- TypeScript / Node 20 local CLI
- SQLite local memory store under `.hermes/`
- Human-approved memory intake
- Draft review
- Approve/reject flow
- Approved memory list/search
- Deterministic reflection from approved memory
- JSON export
- Doctor command
- No required LLM/API calls

## Implemented CLI Commands

- `hermes init`
- `hermes intake --text "..."`
- `hermes intake --file <path>`
- `hermes review`
- `hermes approve <draft-id>`
- `hermes reject <draft-id>`
- `hermes list`
- `hermes search "<query>"`
- `hermes reflect "<question>"`
- `hermes export --json`
- `hermes doctor`

## Safety Boundaries

- HERmes is CLI-only for v0.1.0.
- Runtime data is written under `.hermes/`.
- File intake reads only an explicitly supplied file path.
- Intake creates drafts; approval creates approved memory.
- Approved memories are never hard-deleted.
- `list`, `search`, `reflect`, and `export` read approved memory only.
- Human approval remains mandatory before anything becomes approved memory.
- HERmes does not act on the outside world.

v0.1.0 does not include:

- LLM/API provider
- Claude/Anthropic provider
- Local model/Ollama provider
- Web UI
- Connectors
- Scheduler
- Browser automation
- Shell execution
- Autonomous action
- Correction/supersession/tombstone commands yet

## Current Limitations

- Deterministic intake and reflection only
- No LLM wording provider
- No local model provider
- No correction/supersession/tombstone commands
- No advanced retrieval or full-text search
- No web interface
- No external connectors or automation surfaces
